# ADR 0003 — AOT

- **Estado:** aceite
- **Data:** 2026-11-27

## Contexto

Há o requisito de AOT em todos os projectos onde for possível. O EF Core classifica o suporte a Native AOT como experimental e não suporta queries dinâmicas nesse modo (ver Evidência).

## Decisão

Todas as bibliotecas são compatíveis com AOT (`IsAotCompatible`, analisadores de trimming e AOT a falhar o build, JSON por source generators, sem reflexão). Publicam em Native AOT os executáveis onde isso é suportado. Hosts com EF Core correm em JIT com ReadyToRun enquanto o Native AOT do EF Core for experimental. O modelo compilado só se usa quando o EF Core o suportar com filtros globais.

## Alternativas consideradas

- **Native AOT em todos os executáveis, incluindo os que usam EF Core:** rejeitada; o suporte é experimental e desaconselhado em produção.
- **Abdicar de AOT:** rejeitada; perde-se o arranque rápido e a disciplina sem reflexão nas bibliotecas.

## Consequências

- Os hosts com EF Core correm em JIT.
- O suporte de Native AOT do EF Core tem de ser reavaliado em cada versão.
- O filtro global por empresa (ADR 0008) mantém-se. Enquanto o EF Core não gerar modelo compilado com filtros globais, os hosts constroem o modelo no arranque.
- O custo de arranque sem modelo compilado mede-se na Fase 1, com o modelo real.
- Em AOT, o EF Core só executa queries pré-compiladas; a query dinâmica da prova (um `Where` condicional) falha em AOT. A pré-compilação também rejeita essas queries.

## Evidência

Teste exploratório com um modelo mínimo (uma entidade `Factura` com filtro global por empresa) sobre PostgreSQL 17 em Docker. Máquina Windows 11 em ARM64; publicação nativa com `-r win-arm64` (as ferramentas C++ estavam disponíveis, não foi preciso o contentor Linux). Código descartável, não versionado.

### Ajustes ao teste

- RID `win-arm64` em vez de `win-x64`, por a máquina ser ARM64.
- Linha de base em JIT com `-p:PublishAot=false`, pelo motivo da tabela.
- Variantes extra, só para ver o que funciona sem o filtro: filtro removido; criação da base de dados saltada em AOT (`EnsureCreated` exige o modelo de desenho); query dinâmica removida.

### Conclusão

O filtro global por empresa e as queries dinâmicas, ambos necessários ao siGestão, não funcionam em Native AOT com o EF Core 11.0.0. Nem o modelo compilado em JIT aceita o filtro global. A decisão fica: bibliotecas compatíveis com AOT e hosts com EF Core em JIT, sem modelo compilado enquanto o EF Core não o suportar com filtros globais. Reavaliar em cada versão do EF Core.
